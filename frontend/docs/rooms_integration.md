# 내 방 화면 연결

내 방 목록 → 방 상세·입력 현황 → 추천 코스 예시 → 약속 확정 흐름을 구현했습니다.
첨부 이미지의 흰색 카드, 둥근 테두리, 주황색 포인트를 참고했습니다.
샛로그의 실제 화면을 제공받으면 추가로 디자인을 조정할 수 있습니다.
기존 로그인·홈 화면에 연결했습니다. 홈의 방 카드는 상세 화면을 열고,
오른쪽 위 `내 방` 버튼은 상태별 목록을 엽니다.

## 홈 화면과 공유하는 데이터

`HomeScreen`이 빈 `RoomsController`를 한 번 만들고 종료 시 해제합니다.
홈과 내 방 목록의 만들기 버튼은 기존 `CreateRoomScreen`을 열며,
생성된 방을 공통 `PlanRoom` 모델로 변환해 같은 컨트롤러에 추가합니다.
방 생성 직후 두 목록과 상세 화면에서 같은 이름·초대 코드·참여자를 확인할 수 있습니다.
홈에 따로 있던 `PlanRoom` 모델은 공통 모델로 통합했습니다.

현재 생성 화면은 날짜·지역을 받지 않으므로 생성한 방에는 `날짜 미정`과
`지역 미정`을 표시합니다. 상세의 `약속 날짜 정하기`에서 날짜·시간을 정하면
홈 왼쪽 아래에서 여는 앱 캘린더에 자동으로 반영됩니다. 날짜 변경과 일정 해제도
달력에 반영됩니다. 날짜가 없는 방은 상태별 목록에서 날짜가 있는 방 뒤에
배치합니다. 생성자는 취향 미입력 상태이며, 실제 취향 입력과 AI 생성은 서버 연동 전까지
동작하지 않습니다. 데모 약속을 실제 생성 목록에 자동으로 넣지 않습니다.

```dart
import 'package:meetsync/services/rooms_controller.dart';
import 'package:meetsync/screens/rooms/rooms_screen.dart';

// 메인 화면 State에서 한 번 생성합니다.
final roomsController = RoomsController.demo();

// 하단 내비게이션의 내 방 탭에 연결합니다.
RoomsScreen(controller: roomsController)

// 부모 State.dispose()에서 roomsController.dispose()를 호출합니다.
```

선택적으로 `onCreatePlan`에 약속 만들기 화면으로 이동하는 함수를 전달하세요.
전달하지 않으면 만들기 버튼은 표시하지 않습니다.
`onConfirmed(PlanRoom)`는 이 실행 세션에서 최초 확정 시 한 번 호출됩니다.
이는 동기 UI 알림용 콜백이며 서버 저장 트랜잭션이 아닙니다.
실제 저장 API를 연결할 때는 권한 검사, 실패 처리, 참여자 공유와 캘린더 등록을
백엔드에서 보장하는 비동기 확정 로직으로 교체해야 합니다.

## 현재 범위

- 날짜순 약속 방 목록, 상태 필터, 빈 목록
- 방 상세 정보, 초대 코드 복사, 참여자별 입력 여부
- 사전에 작성한 코스 예시 표시
- 확인 대화상자 후 로컬 상태 확정, 뒤로 이동해도 목록에 즉시 반영
- 부모가 소유하는 컨트롤러로 탭 이동 중 상태 유지

데모 데이터와 변경사항은 메모리에만 보관됩니다. 실제 초대·참여,
개별 취향 입력, LLM 호출, 장소 검색, 로그인 사용자별 권한,
서버 저장 및 외부 캘린더 자동 등록은 아직 연결하지 않았습니다.
앱 실행 시에는 기존 로그인 화면이 나옵니다. 로그아웃하면 로컬 방 상태도 초기화됩니다.

## 검증

코드 정적 분석과 `flutter test --no-pub`를 실행해 검증합니다.
`test/rooms_test.dart`는 확정 중복 방지, 상태 필터, 화면 이동·확정 취소,
빈 목록 및 작은 화면을 검증합니다. `test/widget_test.dart`는 로그인 입력 검증,
프로필 수정 유지·로그아웃·새 세션, 방 생성 후 홈·목록·상세 데이터 공유를 검증합니다.
