# 백엔드 통합 작업 현황 (2026-11-07)

이 문서는 팀원들이 처음 개발한다고 가정하고 작성했습니다.

## 무엇을 합쳤나요?

이 코드는 채연씨가 올린 `feature/home-backend`를 복사해서 만든 **별도 통합 시험 공간**입니다. 기존 채연씨 코드와 원준님의 마이페이지·캘린더 코드를 모두 포함합니다. **공식 main에는 아직 적용하지 않았습니다.**

- 채연씨: 회원가입/로그인, 약속 방 만들기/참여/나가기, 참여자별 약속 조건, 장소 검색, AI 코스 추천, 변경안 동의/투표, 채팅
- 원준님 마이페이지: 프로필 정보, 로그인 아이디/닉네임/비밀번호 변경, 기본 성향, 탈퇴 신청 및 취소, 고객센터/후원 링크
- 원준님 캘린더: 개인 일정 저장/조회/수정/삭제, 외부 캘린더 연결을 위한 서버 API, 일정 충돌 감지, 외부 삭제 확인

## 이번에 실제로 연결한 기능

**기본 성향 → AI 추천**

사용자가 마이페이지에 성향을 저장하면 AI 추천 전에 약속 방 참가자들의 정보를 조회합니다. 읽는 필드는 실내/실외 활동 선호, 음주 선호도, 거주 지역, 차량 보유 여부, MBTI입니다. 저장하지 않은 성향은 빈 값으로 처리합니다.

- 사람마다 따로 선택한 성향을 추천 조건에 포함합니다.
- 성향이 바뀌면 AI 추천이 예전 조건을 기준으로 생성되었다는 것을 판별할 수 있도록 버전 값도 바뀝니다.
- 성별과 생년월일은 추천에 필요하지 않아 AI에 보내지 않습니다.
- 예산, 약속 날짜, 공동으로 합의한 조건이 개인 성향보다 우선입니다.

**나만 방 나가기**

채연씨가 이미 `DELETE /rooms/{room_id}/members/me`를 구현해 두었습니다. 한 사람이 나가면 나머지 참여자는 그대로 두고, 방장이 나가는 경우 남은 사람에게 방장을 넘깁니다. 방에 아무도 남지 않으면 방과 초대 코드가 삭제됩니다. 중복 구현하지 않았습니다.

**아이디 변경과 기존 로그인**

마이페이지의 아이디 변경 기능과 채연씨 로그인 API가 공존하도록 같은 파일 안에서 연결했습니다. 기존 Firebase UID와 사용자별 로그인 아이디를 구분합니다.

## 아직 구현하지 않은 것

1. **확정된 약속 → 캘린더 자동 등록**: 현재 AI 추천은 `rooms/{room_id}/recommendations/latest`에 저장되지만 추천과 사용자가 최종 확정한 약속이 구분되어 있지 않습니다. 방장이 확정하는지, 전원 동의가 필요한지를 결정한 후 구현해야 합니다. 추천만 생성되었다는 이유로 캘린더에 일정을 등록하지 않습니다.
2. **지난 약속 내역**: 현재 `rooms`의 `member_uids`는 현재 참여자만 포함합니다. 나간 사람의 기록을 따로 보관할 방식이 필요합니다.
3. **약속 날짜 변경**: 날짜 변경 시 참여자들의 조건과 AI 추천을 다시 검증해야 합니다. 방장만 가능한지, 전원이 동의해야 하는지 정책이 정해지지 않았습니다.
4. **실제 휴대폰 캘린더 동기화**: Flutter 담당자가 기기 캘린더 접근 권한, 읽기/쓰기, 동기화 실행을 구현해야 합니다.
5. **실제 Firebase/외부 API 통합 검증**: GitHub 자동 테스트는 가상 데이터로 실행합니다. Firebase gRPC 연결 및 외부 서비스 실기기 검증은 별도 확인이 필요합니다.
6. **자동 회원 탈퇴 삭제 실행**: 관리자용 안전장치 스크립트만 있으며 실제 서버 스케줄은 미설정 상태입니다.
7. **프로필 사진 업로드, 자기소개, 상세주소**: 프론트엔드 화면과 서버 저장 규격을 아직 통일하지 않았습니다.

## 확인된 중요한 차이점

채연씨의 현재 GitHub 백엔드는 이름과 달리 Gemini API 직접 호출이 아니라 `OPENROUTER_API_KEY`와 `OPENROUTER_MODEL` 설정을 사용합니다. 또한 추천 날짜는 사용자들이 입력한 `rooms/{room_id}/preferences/{uid}.available_date`를 통해 모으고, 추천 결과는 `rooms/{room_id}/recommendations/latest`에 저장합니다.
